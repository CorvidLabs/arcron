## 1. Current create / sign / update / freeze flow

**Create** (`scripts/govern.py` `create`): requires a configured multisig and `--expect-creator` equal to `ms.address()`. On MainNet, `net.connect` runs first and already demands that address be `NHQU7QBDTUC4Q5I7LV3A35GGG36QUK5EL6PM4ZVBJKZ7AS6EDOU7BCRDWA`. Refuses a dirty tree unless `--allow-dirty`, rebuilds, reads schema from the ARC-56 spec, sets `extra_pages = (len(approval)+len(clear)-1)//2048`, prints the coordinator checklist, optionally asks for the creator address (`--yes` skips that), writes `ApplicationCreateTxn` (NoOp, index 0) via `export_unsigned`.

**Show**: `net.connect` (so MainNet show/sign still need a live node + the MainNet env gates), then decodes the **blob**, not the JSON. For `index==0` and a non-empty approval it prints extra pages, schema, and combined+per-program digests.

**Sign**: prints `describe_transaction`, then `_refuse` (rebuilds keeper artifacts unless `--no-rebuild` or the file carries no approval), then `input()` of the **full** blob address with **no** `--yes`. Then `ms.sign`.

**Update**: on-chain `frozen` must be 0; rebuild; if digest already matches, no-op. Multisig → `ApplicationUpdateTxn` with `update()void` selector, no extra_pages/schema (algosdk: both default means “keep sizes”). Single-key `DEPLOYER` signs in-process on networks that allow it.

**Freeze**: one-way `frozen=1` via `freeze()void` NoOp. Multisig writes a file; `--yes` only skips the **coordinator** app-id prompt.

**Submit**: `_refuse` again, then `ms.submit` (blob threshold, not JSON).

On-chain: `update` is the only `UpdateApplication` route; it asserts creator + `frozen==0` and returns. `freeze` writes `1` and never writes `0`. Bare create is NoOp + app id 0. `bareActions.call` is empty. Delete is not routed.

## 3. Remaining attacks (ranked)

1. **Update can change extra pages and global schema; `show`/`sign` ignore that.**  
   Algorand v42 / algosdk: non-zero `apep` or `apgs` on `UpdateApplication` **replaces both absolutely**; omit one and it goes to **zero**. Honest `govern update` omits both (keep sizes). A hostile file with matching bytecode + `extra_pages`/`global_schema` set:
   - is **not** described as a size change (`describe_transaction` only dumps those fields for creates);
   - is **not** refused;
   - combined digest still matches.
   Effects: drain/move creator MBR (SizeSponsor = sender), shrink schema/pages and brick the app, or grow slots for a later program (that later program still has to pass digest unless `--no-rebuild`).  
   **Confirmed in tooling + current algosdk/protocol docs. Suspected on a given network until you check genesis has `AppSizeUpdates`.**  
   Same class as the old create swap, now on **update**, where holders were told it was impossible.

2. **Create extra_pages / schema still display-only.**  
   Compromised coordinator keeps honest programs (digest passes) and changes pages/schema. `sign` will not refuse (`refusals` never reads `extra_pages` or schema). Too-small global ints fail at `__init__` (2 uints). Too-large is permanent MBR griefing. Local schema is still create-only on-chain.  
   **Confirmed.**

3. **`--no-rebuild` and empty-approval skip the only program check.**  
   Help text says “update: trust the built artifacts” but the flag is on the parser for **sign/submit** (`govern.py:359,324`). `carried_programs` is false if approval is empty even when clear is present.

4. **Freeze/NoOp files: no selector check.**  
   `app_args` printed as hex, never compared to `freeze()void`. Wrong method is a social-engineering miss, not a silent rekey. DeleteApplication with matching `--app-id` **passes `refusals`**; keeper TEAL then rejects (`govern_e2e.py:111-125`; `Keeper.approval.teal:35-45` `OnCompletion` must be 0 for non-update).

5. **MainNet single-key create via this CLI: no. Via other Python: yes.**  
   `load_network("mainnet")` ⇒ flag + exact 3-of-5. `deploy.py` then refuses because a multisig **is** configured. `govern create` also refuses without a multisig.  
   `smart_contracts/keeper/deploy_config.py:15-28` uses `AlgorandClient.from_environment()` + `DEPLOYER` and **never** calls `load_network` / `require_mainnet_multisig`. Anyone who points algod at MainNet and runs that factory still creates from a single key. `fledge run deploy-mainnet` is not that path.

6. **Rekey of the 3-of-5** is refused unless `--account-txn` **and** `--i-mean-to-rekey`. `--i-mean-to-rekey` also allows payment/asset closes. Blob address is the check; JSON `address`/`threshold`/`signers` are decoration (`export_unsigned` vs `blob_*`). Threshold is part of the address, so a 1-of-5 with the same members is a different address and is refused.

7. **Create vs update confusion** is mostly closed: `in_file != app_id` plus create detection `index==0 and approval`. Signing a create with `--app-id N` or an update with `--app-id 0` refuses.

8. **Sign TOCTOU (low):** describe + refuse, then `input()`, then `sign` rereads the file. Confirmation is only the sender address, not the digest. Relevant if the file sits on a coordinator-controlled path.

9. **Dirty-tree check has no `cwd=REPO`** (`govern.py:193-194` vs `verify_build.py:103-108`). `git status` from the wrong directory can look clean. Coordinator-side.

## 2. Remaining money-loss / user-loss paths

### Confirmed

**A. Console still trusts the app’s own `frozen` flag.**  
`isFrozen` reads global state the creator controls (`arcron.service.ts:47-55`). `noticesFor` warns only when `frozen === false` (`trust-banner.ts:74-85`). A lookalike can store `frozen=1` and remain upgradeable. The *identity* banner still fires for a non-canonical id. Freeze can be silenced; “wrong app” cannot.

**B. JS decoder does not fingerprint the struct; the Python bot does.**  
A hostile or old `u*` box with a non-130 tail offset is rejected by the bot and accepted by JS/web as a plausible upkeep (often with empty `callArgs`). That keeps `undecodableBoxes === 0`, so the “does not decode” banner never appears.

Python (`scripts/keeper_bot.py:214-222`):

```python
tail_offset = int.from_bytes(raw[40:42], "big")
if tail_offset != HEAD_BYTES:
    raise ValueError(...)
```

JS (`js/src/upkeep.ts:104-117`) uses `tailOffset` as a pointer and never checks `=== 130`. JS tests do not pin the offset reject (`js/test/upkeep.test.ts:84-86` only checks truncation).

On the recorded 1.0 bytes with offset patched to 82: `getUint16(82) === 0` → `callArgs = []` → decode “succeeds”.

**C. Console can register an ASA bonus and cannot finish or fund it.**  
Register exposes `feeAsset` / `assetFee` (`register-form.ts:67-78`). `KeeperService.optInAsset` / `topUpAsset` exist (`keeper.service.ts:52-68`) but no component calls them. User escrows ALGO believing a token bonus is live; keepers never see it. Cancel can still return ALGO. Not theft; it is a setup trap.

**D. JS `execute` overpays the ASA inner fee whenever the signer is opted in.**  
Contract pays the bonus only if escrow, opt-in, real holding, and freeze all pass (`contract.py:410-417`).

Python bot matches three of those (`keeper_bot.py:561-566`).

JS (`keeper-txns.ts:219-226`):

```ts
const paysBonus = usesAsset && (await optedIn(algod, signing.sender, upkeep.feeAsset ?? 0n));
```

No `assetBalance` (and `execute`’s type is `Pick<Upkeep, 'id' | 'targetApp' | 'feeAsset'>`). Unused pooled fee is not refunded. **~0.001 ALGO per such execution**, console Execute included.

**E. Hardcoded inner-fee budget: two inners, plus one for a bonus.**  
Bot `EXTRA_FEE_MICROALGO = 2_000`; JS `EXECUTE_FEE = 3_000` (+1_000). The inner target call is built with no extra fee (`contract.py:437-453`). A target that itself submits inners is unserviceable by bot and JS. The JS spike says so (`spike_js_execute_resources.py:18-23`). **Service loss, escrow stuck until a keeper with a fatter fee shows up** (this client never will).

**F. JS `register` / `topUp` / `topUpAsset` take the node’s suggested fee with no ceiling.**  
`execute` / `cancel` / `optInAsset` use `flatFee`. Register and ALGO top-up do not (`keeper-txns.ts:103-145, 154-176`). A lying algod can put a huge fee on a group the wallet will still prompt. Bot executions *are* capped.

**G. Write path not gated on genesis match.**  
`genesisMatches === false` paints a banner (`app.ts:49-52`, `network-bar.ts:178`) but `canSubmit` / `reads()` only require `status === 'ready'`. Refresh sets `ready` even on a genesis mismatch (`arcron.service.ts:206-223`). Console has no MainNet *picker*; a TestNet config pointed at a MainNet node would still let Register send. Wallet software may still refuse.

**H. Bot `scan_upkeeps` is all-or-nothing.**  
One `u*` box that fails `_decode_upkeep` throws out of the scan (`keeper_bot.py:247-252`). No per-box catch. On a honest 1.0 app this should not happen. Pointed at a mixed/old app, the bot services **nothing**.

## 1. Overview

Arcron is an on-chain bounty board for scheduled Algorand app calls. A creator escrows ALGO (optionally plus an ASA bonus) into a box; anyone who shows up after the due round performs that exact call and is paid from that box. No protocol cut, no required token. That is what the keeper is.

The live TestNet app `769891898` is still **unfrozen**, and this tree’s approval program is **2,178 bytes** (plus 4-byte clear → 2,182 combined, `extra_pages = 1`). That is the known 74-byte move past the deployment from the rekey/close asserts. I am scoring this tree, not the live bytes.

What changed since the 4/10 pass is real. The ten named findings are in the code, not just in the changelog: `SECURITY.md` now states the update path; `govern create` exists; `show`/`sign` describe a create and refuse a program digest that is not this tree; MainNet requires the 3-of-5, not only an env flag; the console identity notice no longer depends on a successful box read; the bot will not fall back to `DEPLOYER` on an unfrozen app; the JS client simulates and attaches foreign refs. Deadman, embargo, watchdog, treasury, and rain’s `default_frozen` gate are actually fixed.

What has not changed is the class of mistake that produced three of those fixes: a demo or a mock hides an MBR floor, the contract books the incoming payment as user money, payouts fail forever, and unit tests stay green. That class is still live in **rain’s ALGO pot** and **subscription**. `docs/status.md` still says the opposite of the code about which examples ship.

I still do not see a way for a stranger to take another creator’s escrow out of **this** keeper bytecode.
