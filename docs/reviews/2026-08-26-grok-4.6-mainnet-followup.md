## extra_pages arithmetic

**Confirmed right at the page boundary.**

```194:194:scripts/govern.py
    extra_pages = (len(approval) + len(clear) - 1) // PROGRAM_PAGE
```

For `n >= 1` this is `ceil(n / 2048) - 1`, and it matches the protocol rule `n <= 2048 × (1 + extra_pages)`:

| combined bytes | extra_pages | capacity | fits |
|---|---|---|---|
| 2048 | 0 | 2048 | yes |
| 2049 | 1 | 4096 | yes |
| 4096 | 1 | 4096 | yes |
| 4097 | 2 | 6144 | yes |

Live keeper: approval 2104 + clear 4 = 2108 → extra_pages **1**, capacity 4096. Combined digest `0afab368…bf49`, identical to `verify_build` (`scripts/verify_build.py:55–57` and `scripts/multisig.py:243–250`).

`n == 0` would yield `-1` (Python floor division). Not reachable for this contract. **Suspected only:** no unit test pins the 2048/2049/4096 cases, so a future “simplify the formula” edit would not fail CI.

## 7. Is `govern create` safe for the real MainNet create?

**No.** Use it as the only writer of the unsigned file, after `0c2f0f1`, on a clean tagged tree, with `--expect-creator NHQU…`. Do not treat the current `show`/`sign` loop as the check of that file.

Before the real create, the sign path has to print, for a create, the same permanent fields create already prints: extra pages, global/local schema, combined digest of both programs, and that this *is* a create. Until that exists, five honest holders glancing at `show` can still authorize the one transaction that cannot be undone.
